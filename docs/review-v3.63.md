## 아기방 치수 검토

[치수 참고도](babyroom-v363-reference.svg)는 현재 앱 **기본값**의 기하학적 일관성을 표시합니다.
사용자의 로그인된 실제 가구 배치나 새 실측 자료를 읽어 만든 시공 도면은 아닙니다.
기기에 저장한 수정 치수는 계속 우선 적용됩니다.

가구 기본 규격은 기존 카탈로그 기록을 유지했습니다. 이번 검토에서 제조사 최신 규격을
별도로 재확인한 것은 아닙니다. 충돌 없음은 2차원 바닥 점유의 계산 결과이며,
가구 문·서랍 개폐, 가구 높이, 콘센트 위치, 실제 통행 여유는 포함하지 않습니다.
외벽 간격은 고정가구나 내부 벽까지의 거리를 뜻하지 않습니다. 이들은 별도 충돌 판정입니다.

## 전체 집 도면의 남은 확인

현재 소스의 전체 외곽·방 원점·복도 연결 좌표는 각 방 실측 기본값과 일치하지 않는 부분이 있습니다.
임의로 늘이거나 줄여 연결하지 않고 참고도임을 표시했습니다. 전체 집 화면은 가구 배치 편집을
막고 각 방에서 편집하도록 했습니다. 정확한 통합도를 만들려면 최신 원도면과 다음 값이 필요합니다.

- 각 방과 복도가 만나는 벽의 시작점, 벽 두께, 개구부 양끝
- 세탁실 깊이와 좌하단 꺾임, 부부욕실 사선, 공용부 단계별 폭·세로
- 아기방 두 꺾임의 실제 치수 및 창호 프레임/개폐 방향

## 검증 범위와 운영 상태

`npm test`는 실제 앱 스크립트와 도면 엔진을 사용해 저장·동기화·충돌 회귀를 확인합니다.
동기화 테스트는 Firestore 경계를 대체한 결정적 테스트로 운영 데이터에 접근하지 않습니다.
현재 로컬 회귀 테스트는 **43개 모두 통과**했습니다. `git diff --check`와 브라우저 테스트 스크립트의
구문 검사도 통과했습니다. `npm run test:browser`에는 PC(1440×1000), 모바일(390×844)의 Chromium에서
가구 추가·이동·회전·방 전환·삭제·전체 방 렌더링·재접속을 확인하는 절차를 준비했습니다.
GitHub Actions의 Chromium에서 **PC·모바일 검사 모두 통과**했습니다.
검증 커밋: `5c9b08e6113cbab50386a1e906b14e0d54518887`.
[검사 실행 결과](https://github.com/Max-Parks/Park-s-Fam/actions/runs/37318884602)에는
43개 회귀 테스트, 두 화면 크기의 브라우저 검사와 캡처 파일이 포함됩니다.
초기 검사에서 단독 SVG 문서의 전체 화면 캡처가 시간 초과되어, 같은 SVG를 HTML 이미지로
표시하고 디코딩 완료 후 캡처하도록 검사 코드만 수정했습니다. 앱 동작 검사는 생략하지 않았습니다.

GitHub 연결 도구의 쓰기 권한 오류 이후 사용자 승인하에 브라우저로 검증 브랜치를 반영했습니다.
수정 이력과 병합 상태는 [PR #1](https://github.com/Max-Parks/Park-s-Fam/pull/1)에 기록됩니다.
운영 주소는 기존 https://max-parks.github.io/Park-s-Fam/ 을 사용합니다.

Firebase 콘솔 접속을 복구해 2026-10-05 22:19 KST에 `firestore.rules`를 운영 게시했습니다.
기존 운영 규칙도 이미 같은 네 가족 계정을 제한하고 있었습니다. 이번 변경은 그 제한을 유지하며
허용 방 ID와 문서의 roomId 일치, items 배열, 선택적 geometry 객체 형식을 검사합니다.
geometry 필드는 구버전의 방 간 이동 저장과 호환되도록 생략을 허용합니다.
게시 전 규칙 플레이그라운드에서 비로그인 읽기 거부, 가족 읽기 허용, 미등록 계정 읽기 거부,
geometry 없는 구버전 형식 생성 허용, 경로와 roomId가 불일치하는 생성 거부를 확인했습니다.
규칙 검사에서 실제 가족 문서를 생성하거나 수정하지 않았습니다. 실제 앱의 Google 로그인과
두 기기 간 공동 저장은 아직 확인하지 않았습니다. 이전 운영 규칙은 Firebase 콘솔의 규칙 버전 기록에서 확인할 수 있습니다.
기존 APK 바이너리와 서명은 변경하지 않았고, APK가 여는 기존 웹 주소를 유지했습니다.
